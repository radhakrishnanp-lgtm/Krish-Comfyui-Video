# Krish Frame Conform (ComfyUI, LTX)

Makes LTX video-to-video return **exactly the same frame count, order and size** as the input.

LTX needs 8n+1 frames and width/height divisible by 32. ComfyUI's LTX nodes crop or round anything else,
so frames get lost and the duration drifts. These nodes pad onto the grid before sampling and trim after.

## Install
Copy the whole `Krish-Comfyui-Video` folder into `ComfyUI/custom_nodes/` and restart.

## Workflow
```
Load Video -> Krish LTX Frame Prep -> (LTX conditioning/sampler/VAE decode) -> Krish LTX Frame Restore -> Parity Check -> Save
                  |  conform_info ------------------------------------------^
                  |  num_frames / width / height -> LTX latent size inputs
```
- **Prep** pads the tail (repeat or ping-pong) and the edges (reflect). Original pixels are never resampled.
- **Restore** trims the padding. If the model returned another frame count or size, it retimes/resizes back and
  reports what it fixed. Optional `source_images` + `mask` keep unedited regions pixel-exact from the source.
- **Parity Check** errors if count or size ever differs from the source.
- Set the video combine fps to the source fps. These nodes do not change timing.

Note: the VAE round trip changes pixel values inside the edited area. These nodes guarantee count, order,
size and timing. Use the mask input for pixel-exact preservation elsewhere.

## Ready-made workflow
Drag `workflows/krish_ltx_exact_frames_v2v.json` into ComfyUI (core nodes only plus the Krish nodes).
Then set: checkpoint, CLIP/text encoder, input video, prompt. `Denoise` (default 0.5) controls how much of the
original is kept. It runs Load Video -> Prep -> VAE Encode -> LTX sampler -> VAE Decode -> Restore -> Parity Check
-> Create Video (source fps and audio) -> Save.
It is regenerated by `python3 tools/build_workflow.py`.

## Max-quality variant (96 GB GPU, dev model)
`workflows/LTX_Workflow_02_Krish_MaxQuality.json` (`python3 tools/make_max_quality.py <patched.json> <out.json> [shorter_size] [dev|distilled]`):
`ltx-2.5-22b-dev-transformer-bf16` + bf16 Gemma, LTXVScheduler 40 steps, CFG 4, euler, full (non-tiled) VAE decode,
1440 generation size, and a 16-bit PNG sequence output. Expect it to be much slower than the distilled 8-step setup.
The step count, CFG and sampler are starting values, not tuned for 2.5. If you run out of memory, lower the size to 1088.

## LTX 2.5 Matte Gen - no audio (VFX)
`workflows/LTX_2.5_Matte_Gen_NoAudio_Krish.json` (`python3 tools/patch_matte_no_audio.py <original.json> <out.json>`):
no audio decode/save/export; **Krish Matte Frame-to-Frame Check** (count, NaN/Inf, range, time shift, duplicated frames,
isolated dropouts, flicker spikes) plus a FINAL parity check of the deliverable against the original loaded frames.

Matte check notes: count, NaN/Inf, range, duplicated frames and isolated dropouts always stop the run on failure.
The time-shift test compares each matte frame's edge structure with the source frames around it and needs strong,
consistent evidence; by default (`alignment: warn`) it only reports. Set `alignment: strict` to make it stop the run.
Prep only pads the tail and Restore trims it, so these nodes cannot shift frames; the test exists to catch the model.

## Updating the node pack
ComfyUI keeps the old node code until it restarts. Pull the latest into `ComfyUI/custom_nodes/Krish-Comfyui-Video`
(`git pull origin claude/relaxed-bardeen-xyfs5r`, or re-download the branch zip and replace the folder), restart ComfyUI,
then load the workflow file again. In the Matte Gen workflow the matte check is a report-only side branch: it can no longer
stop the frames. Only the Parity checks (frame count / size vs the original) can stop a run.

## DepthCrafter workflow (exact frames + fps)
`workflows/DepthCrafter_Krish_ExactFrames.json` (`python3 tools/patch_depthcrafter.py <original.json> <out.json>`) for
[ComfyUI-DepthCrafter-Nodes](https://github.com/akatz-ai/ComfyUI-DepthCrafter-Nodes). DepthCrafter already returns one depth
map per input frame and the workflow scales back to the loaded size, so no padding is used. A FINAL Krish Parity Check compares
the finished frames with the original loaded frames (count, width, height) and stops with an error if they differ. Output fps is the
source fps. None of the LTX nodes or workflows are touched.

## Soft frames at the start of an LTX matte (tiled VAE decode)
`tools/fix_tiled_decode.py` swaps `VAEDecodeTiled` for a full `VAEDecode`. With `temporal_size 64` the LTX VAE decodes 8 latent
frames = 57 pixel frames (0..56) per tile and blends neighbouring tiles, which softens fine detail around the tile boundary.

## EXR in -> EXR out (same colour tags, metadata, channels, frame numbers)
Install the backend into the Python that runs ComfyUI: `python -m pip install OpenEXR` (also listed in `requirements.txt`).
If it is missing, only the EXR nodes report that; the LTX nodes are unaffected.

| Node | What it does |
|---|---|
| **Krish EXR Load** | File, folder or pattern (`plate.%04d.exr`, `plate.####.exr`) -> unclamped float32 `images`, true `alpha`, `exr_meta`, `info`, frame count, width, height, **fps from the file**. Pick a `layer` / `part_index` for AOVs and multi-part files. |
| **Krish EXR Save** | For every frame it re-opens the **original EXR** and replaces only the channels you choose, so everything else is carried over as it was. Output keeps the **source frame numbers**. |
| **Krish EXR Linear -> Display** | Scene-linear -> display 0..1 for models (sRGB / Rec.709 / gamma / **ACEScct log**, exposure, `clip` or `soft_knee`). |
| **Krish EXR Display -> Linear** | Inverse curve, never clamps. |

**Save modes:** `replace_rgb` (images become R,G,B(,A)) | `matte_to_alpha_keep_rgb` (source RGB untouched, matte in A) |
`matte_only_alpha` (file holds only the matte) | `matte_as_gray_rgb`. `keep_other_channels` keeps AOVs, other layers and other parts.

**Preserved verbatim:** every header attribute (chromaticities, `colorInteropID`, `oiio:ColorSpace`, `framesPerSecond`, timecode,
matrices, vectors, arrays, custom/vendor keys), data window vs display window (overscan/crop), pixel aspect, line order, tiling,
part names, per-channel pixel type (half stays half, float stays float, uint stays uint), and compression. With `verify: strict`
every written header is re-read and compared with the source; any difference stops the run and names the attribute.
Source files are never overwritten, and files are written atomically.

**Colour space:** EXR has no mandatory colour-space field. The nodes copy the tags unchanged and never convert primaries; the
`info` output names the space (e.g. `lin_ap0_scene`). The Linear <-> Display nodes only change the transfer curve for the model.

**Matte workflow wiring (LTX):** `Krish EXR Load` -> `Krish EXR Linear -> Display` (clip) -> Resize -> `Krish LTX Frame Prep` -> LTX ...
-> `Krish LTX Frame Restore` -> scale to the loader's `width`/`height` -> `Krish EXR Save` (`matte_to_alpha_keep_rgb`, `exr_meta`
from the loader). Use the loader's `fps`, `width`, `height` where the video workflow used VHS Video Info.

**Limits:** lossy DWAA/DWAB sources are re-compressed (second generation of loss) for channels the node does not change; the
report warns, and choosing `ZIP`/`PIZ` keeps them bit-identical to the decoded source. Half output is clamped to +-65504 instead of
overflowing to inf. Deep EXR and subsampled (YC) channels are not supported. If the source frame is gone at save time, the header
stored at load time is used and only the channels you write are saved.

**Which transform?** Mattes and other data you only *read* from the model need no way back, so `sRGB` + `clip` is fine. If the
model's **colour output returns to the EXR** (restyle, deblur, fill, upscale), use `ACEScct (log, invertible)`: its 0..1 covers
scene-linear -0.0069 .. 222.9, and `Display -> Linear` with the same setting is its exact inverse, so highlights come back
instead of clipping at 1.0. It is a curve only (no primaries conversion). Keep bit depth high end to end: quantisation is
magnified by the inverse curve (8-bit ACEScct is about 4.9% per step in linear), so save EXR (or 16-bit+), never 8-bit video, in
the middle of the chain. The loader's `info` prints an `encoding hint` read from the file's colour tags.

## Qwen 2.1 edit with EXR in / EXR out
`workflows/Qwen_2.1_Edit_EXR.json` (`python3 tools/make_qwen_exr_workflow.py <qwen_edit.json> <out.json> [exr_name]`) is the Qwen
inpaint workflow with the PNG plate replaced by `Krish EXR Load` -> `Linear -> Display` (sRGB + soft knee: nothing clipped) and the
output replaced by `Krish EXR Keep Original Outside Edit` -> `Krish EXR Save`. Only the pixels Qwen changed are decoded; every other
pixel is the original linear pixel, bit for bit (checked on a real 4096x2304 half-float PIZ frame: same header, timecode, fps,
type, compression and frame number). The mask PNG must be the same size as the EXR. The original workflow file is not modified.

## Upload button on Krish EXR Load
`web/krish_exr_upload.js` adds **choose EXR file(s) to upload** at the bottom of the loader, like Load Image's upload button. It uses
ComfyUI's standard `/upload/image` endpoint and saves into `ComfyUI/input/krish_exr/` with the original file names (overwriting, so
numbered frames stay a sequence). Pick one frame and `path` is filled in; pick several numbered frames and `path` is set to the first
one with `sequence_from_file` switched on. The button is never saved in the workflow, so existing workflows are unaffected.

**Troubleshooting:** at start-up the console prints `[Krish] Krish-Comfyui-Video 0.4.0 loaded: N nodes (EXR nodes: yes, merge node: yes)`.
A Krish node that is red with every widget named `UNKNOWN` means ComfyUI does not know that node: it is still running an older
copy of the pack. Update the folder, restart ComfyUI (not just the browser), and check that line.
