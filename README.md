# Krish Frame Conform (ComfyUI, LTX)

Makes LTX video-to-video return **exactly the same frame count, order and size** as the input.

LTX needs 8n+1 frames and width/height divisible by 32. ComfyUI's LTX nodes crop or round anything else,
so frames get lost and the duration drifts. These nodes pad onto the grid before sampling and trim after.

## Install
Copy the whole `Krish-Comfyui-Video` folder into `ComfyUI/custom_nodes/` and restart.

## Workflow
```
Load Video -> Krish LTX Frame Prep -> (LTX conditioning/sampler/VAE decode) -> Krish LTX Frame Restore -> Parity Check -> Save
                  |  conform_info ------------------------------------------^
                  |  num_frames / width / height -> LTX latent size inputs
```
- **Prep** pads the tail (repeat or ping-pong) and the edges (reflect). Original pixels are never resampled.
- **Restore** trims the padding. If the model returned another frame count or size, it retimes/resizes back and
  reports what it fixed. Optional `source_images` + `mask` keep unedited regions pixel-exact from the source.
- **Parity Check** errors if count or size ever differs from the source.
- Set the video combine fps to the source fps. These nodes do not change timing.

Note: the VAE round trip changes pixel values inside the edited area. These nodes guarantee count, order,
size and timing. Use the mask input for pixel-exact preservation elsewhere.

## Ready-made workflow
Drag `workflows/krish_ltx_exact_frames_v2v.json` into ComfyUI (core nodes only plus the Krish nodes).
Then set: checkpoint, CLIP/text encoder, input video, prompt. `Denoise` (default 0.5) controls how much of the
original is kept. It runs Load Video -> Prep -> VAE Encode -> LTX sampler -> VAE Decode -> Restore -> Parity Check
-> Create Video (source fps and audio) -> Save.
It is regenerated by `python3 tools/build_workflow.py`.

## LTX 2.5 Alpha Gen workflow (patched)
`workflows/LTX_2.5_Alpha_Gen_Krish_ExactFrames.json` is the Alpha Gen workflow with the Krish nodes wired in
(`python3 tools/patch_alpha_gen_workflow.py <original.json> <out.json>`). Your subgraphs, models and LoRA are unchanged.
Prep goes before the Source Video subgraph; Restore + Parity Check go after VAE decode; Audio Restore trims the audio.

## Max-quality variant (96 GB GPU, dev model)
`workflows/LTX_Workflow_02_Krish_MaxQuality.json` (`python3 tools/make_max_quality.py <patched.json> <out.json> [shorter_size] [dev|distilled]`):
`ltx-2.5-22b-dev-transformer-bf16` + bf16 Gemma, LTXVScheduler 40 steps, CFG 4, euler, full (non-tiled) VAE decode,
1440 generation size, and a 16-bit PNG sequence output. Expect it to be much slower than the distilled 8-step setup.
The step count, CFG and sampler are starting values, not tuned for 2.5. If you run out of memory, lower the size to 1088.

## LTX 2.5 Matte Gen - no audio (VFX)
`workflows/LTX_2.5_Matte_Gen_NoAudio_Krish.json` (`python3 tools/patch_matte_no_audio.py <original.json> <out.json>`):
no audio decode/save/export; **Krish Matte Frame-to-Frame Check** (count, NaN/Inf, range, time shift, duplicated frames,
isolated dropouts, flicker spikes) plus a FINAL parity check of the deliverable against the original loaded frames.

Matte check notes: count, NaN/Inf, range, duplicated frames and isolated dropouts always stop the run on failure.
The time-shift test compares each matte frame's edge structure with the source frames around it and needs strong,
consistent evidence; by default (`alignment: warn`) it only reports. Set `alignment: strict` to make it stop the run.
Prep only pads the tail and Restore trims it, so these nodes cannot shift frames; the test exists to catch the model.

## Updating the node pack
ComfyUI keeps the old node code until it restarts. Pull the latest into `ComfyUI/custom_nodes/Krish-Comfyui-Video`
(`git pull origin claude/relaxed-bardeen-xyfs5r`, or re-download the branch zip and replace the folder), restart ComfyUI,
then load the workflow file again. In the Matte Gen workflow the matte check is a report-only side branch: it can no longer
stop the frames. Only the Parity checks (frame count / size vs the original) can stop a run.

## DepthCrafter workflow (exact frames + fps)
`workflows/DepthCrafter_Krish_ExactFrames.json` (`python3 tools/patch_depthcrafter.py <original.json> <out.json>`) for
[ComfyUI-DepthCrafter-Nodes](https://github.com/akatz-ai/ComfyUI-DepthCrafter-Nodes). DepthCrafter already returns one depth
map per input frame and the workflow scales back to the loaded size, so no padding is used. A FINAL Krish Parity Check compares
the finished frames with the original loaded frames (count, width, height) and stops with an error if they differ. Output fps is the
source fps. None of the LTX nodes or workflows are touched.
